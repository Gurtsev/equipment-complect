# Дорожная карта разработки

## Сценарий: несколько пользователей, с разных устройств

Этап 1 (localStorage) пропускается — его заменяет бэкенд в Этапе 3.

---

## ✅ Этап 2 — Расширение функциональности

Данные по-прежнему in-memory. Все фичи работают в рамках одной сессии.

### ✅ 2.1 Расширенные фильтры и сортировка в каталоге
- Фильтр по статусу оборудования
- Фильтр по локации
- Сортировка: по названию, по дате добавления, по статусу
- Кнопка "Сбросить фильтры"

### ✅ 2.2 Редактирование оборудования
- Кнопка "Редактировать" в карточке оборудования
- Открывает drawer с предзаполненными данными
- После сохранения карточка обновляется

### ✅ 2.3 Указание ответственного при обновлении статуса
- Поле "Кто меняет" в форме обновления статуса в EquipmentDetail
- Записывается в историю вместо изначального владельца

### ✅ 2.4 Дашборд — сводная статистика
- Всего единиц оборудования
- Разбивка по статусам
- Разбивка по категориям
- Разбивка по локациям

### ✅ 2.5 Экспорт списка в CSV и Excel
- Кнопка "Экспорт" в каталоге
- Экспортирует текущий отфильтрованный список
- CSV — без зависимостей, нативный Blob
- Excel — библиотека xlsx, отдельный лист с историей изменений

### ✅ 2.6 Печать карточки оборудования
- Кнопка "Печать" в карточке оборудования
- CSS @media print: скрыть лишнее, показать QR-код и историю
- window.print() по клику

### ✅ 2.7 Проекты и комплекты оборудования
- Новая сущность "Проект": название, клиент, даты, локация, ответственный
- Статусы проекта: Планируется → Активен → Завершён
- Новый статус оборудования: "Забронировано"
- Прикрепление оборудования к проекту, проверка конфликтов
- Массовая выдача / возврат комплекта
- Вторая вкладка в сайдбаре — список проектов
- Карточка проекта с составом комплекта
- В карточке оборудования: поле "Проект" (если занято)
- Экспорт листа выдачи комплекта

## ✅ Этап 3 — Коллаборация

Данные переезжают на сервер. Появляются пользователи и роли.

### ✅ 3.1 Бэкенд — Supabase (PostgreSQL + готовый API)
- Таблицы: equipment, equipment_history, projects, project_equipment
- Фронтенд переключается с in-memory репозитория на Supabase JS SDK (`@supabase/supabase-js`)
- Сервисный слой `src/services/` заменяет репозитории: equipmentService, historyService, projectService
- Переменные окружения: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` в `.env`
- RLS отключён на этом этапе — включается в 3.2 вместе с авторизацией

### ✅ 3.1.1 Supabase Storage — изображения оборудования
- Публичный bucket `equipment-images`
- В форме добавления/редактирования оборудования: компонент `<Upload>` (Ant Design) вместо текстового поля URL
- Файл загружается в bucket, в поле `image` таблицы `equipment` сохраняется публичный URL
- Допустимые форматы: JPEG, PNG, WebP; рекомендуемый размер — до 2 МБ

### 3.2 Авторизация и роли
- Вход по email + пароль (Supabase Auth)
- Роли: Администратор / Оператор / Наблюдатель
- Без входа — доступ закрыт
- RLS включается здесь

| Роль | Права |
|---|---|
| Администратор | Всё: создание, редактирование, удаление, управление пользователями |
| Оператор | Добавление оборудования, смена статуса, редактирование, работа с проектами |
| Наблюдатель | Только просмотр |

### 3.3 История изменений с указанием пользователя системы
- Каждая запись истории содержит user_id из Supabase Auth
- В UI показывается имя пользователя, а не только "ответственный"

### 3.4 Синхронизация в реальном времени
- Supabase Realtime subscriptions
- Изменения одного пользователя мгновенно отображаются у всех остальных

### 3.5 Управление пользователями
- Страница администратора: список сотрудников
- Приглашение по email, назначение роли, деактивация аккаунта

### 3.6 Коллаборация по проектам
- Проекты видны всем пользователям в реальном времени
- Защита от конфликтов: нельзя добавить занятое оборудование
- Уведомление при попытке занять уже занятую единицу
- Календарный вид: какое оборудование занято в конкретный день
- История на уровне проекта: кто что добавил / убрал

## Итоговый результат

Веб-система управления инвентарём студии, доступная с любого устройства по ссылке.

- Весь инвентарь виден в реальном времени всем сотрудникам
- Полная история перемещений с указанием пользователя
- Проекты и комплекты: резервирование, выдача, возврат
- Роли: кто что может делать
- Экспорт в Excel и печать карточек для офлайн-работы
