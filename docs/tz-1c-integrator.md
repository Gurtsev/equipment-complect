# ТЗ для интегратора 1С

Документ описывает требования к HTTP-сервису на стороне 1С для интеграции с веб-системой управления инвентарём студии.

---

## Контекст

Веб-сервис управляет оперативным учётом оборудования: серийные номера, фото, история перемещений, комплекты проектов, временные займы сотрудникам, учёт расходных материалов.  
1С управляет бухгалтерским учётом: принятие к учёту, инвентарные номера, списание.

**Что учитывается в 1С и как:**
- **Студийное оборудование** (камеры, свет, звук и т.д.) — основные средства (балансовый учёт)
- **Мебель, реквизит, АХО** — забалансовый учёт
- **Расходные материалы** — забалансовый учёт

**Связующее звено:** инвентарный номер.  
Веб-сервис выбирает номер из 1С при постановке на учёт, 1С получает серийный номер обратно.

**Подразделения** (студия / АХО / офис) в 1С не ведутся — назначаются вручную в веб-сервисе.

---

## Технические требования к HTTP-сервису

### Протокол и аутентификация

- HTTPS (обязательно — передаются технические учётные данные)
- Аутентификация: **HTTP Basic Auth** (логин + пароль технического пользователя)
- Формат данных: **JSON** (Content-Type: `application/json`)
- Кодировка: UTF-8

---

## Метод 1 — Список свободных инвентарных номеров (ОС)

```
GET /assets/free
Authorization: Basic <base64(login:password)>
```

**Логика в 1С:**  
Вернуть список основных средств, которые:
- Приняты к учёту (введены в эксплуатацию)
- НЕ имеют заполненного поля «Серийный номер» (или флага синхронизации с веб-сервисом)

**Ожидаемый ответ (200 OK):**

```json
[
  {
    "inv_no": "ОС-000123",
    "name": "Камера Sony FX3",
    "category": "Видеотехника",
    "accepted_at": "2024-03-15"
  },
  {
    "inv_no": "ОС-000124",
    "name": "Микрофон Rode NTG5",
    "category": "Аудиотехника",
    "accepted_at": "2024-04-01"
  }
]
```

**Поля:**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `inv_no` | string | ✅ | Инвентарный номер ОС |
| `name` | string | ✅ | Наименование ОС из 1С |
| `category` | string | — | Группа ОС (для справки) |
| `accepted_at` | string (YYYY-MM-DD) | — | Дата принятия к учёту |

## Метод 2 — Привязка серийного номера к ОС

```
POST /assets/sync
Authorization: Basic <base64(login:password)>
Content-Type: application/json
```

**Тело запроса:**

```json
{
  "inv_no": "ОС-000123",
  "serial_no": "SN-A1B2C3D4"
}
```

**Логика в 1С:**  
1. Найти ОС по инвентарному номеру
2. Если поле «Серийный номер» пустое — записать переданный серийный номер
3. Если серийный номер уже заполнен другим значением — вернуть ошибку `conflict`
4. Вернуть актуальные данные по ОС

**Ожидаемый ответ (200 OK):**

```json
{
  "status": "ok",
  "inv_no": "ОС-000123",
  "serial_no": "SN-A1B2C3D4",
  "accounting_status": "active"
}
```

> **Примечание:** МОЛ и подразделение назначаются в веб-сервисе вручную. Из 1С эти поля не требуются.

**Поля ответа:**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `status` | `"ok"` / `"conflict"` / `"not_found"` | ✅ | Результат операции |
| `inv_no` | string | ✅ | Инвентарный номер |
| `serial_no` | string | ✅ | Серийный номер (подтверждение) |
| `accounting_status` | `"active"` / `"written_off"` | ✅ | Статус в бухгалтерском учёте |

**Ответ при конфликте (200 OK):**

```json
{
  "status": "conflict",
  "inv_no": "ОС-000123",
  "message": "Серийный номер уже привязан к данному ОС"
}
```

**Ответ если ОС не найдена (200 OK или 404):**

```json
{
  "status": "not_found",
  "inv_no": "ОС-000999",
  "message": "Основное средство с указанным номером не найдено"
}
```

## Метод 3 — Пакетная проверка статуса ОС (для фоновой синхронизации)

```
POST /assets/status/batch
Authorization: Basic <base64(login:password)>
Content-Type: application/json
```

**Тело запроса:**

```json
{
  "inv_nos": ["ОС-000123", "ОС-000124", "ОС-000125"]
}
```

**Логика в 1С:**  
Вернуть текущий статус по каждому переданному номеру. Используется веб-сервисом для автоматического обнаружения списанных ОС (фоновое задание раз в 30 минут).

**Ожидаемый ответ (200 OK):**

```json
[
  {
    "inv_no": "ОС-000123",
    "accounting_status": "active",
    "written_off_at": null
  },
  {
    "inv_no": "ОС-000124",
    "accounting_status": "written_off",
    "written_off_at": "2025-11-01"
  }
]
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `inv_no` | string | ✅ | Инвентарный номер |
| `accounting_status` | `"active"` / `"written_off"` | ✅ | Текущий статус |
| `written_off_at` | string (YYYY-MM-DD) / null | — | Дата списания |

> **Примечание:** Ранее планировался единичный `GET /assets/status?inv_no=...`. Заменён на пакетный POST для сокращения числа запросов (~100 ОС за цикл).

## Метод 4 — Список забалансовых позиций (АХО и расходные материалы) ⚠️ требует уточнения

```
GET /offbalance/free
Authorization: Basic <base64(login:password)>
```

**Контекст:**  
Мебель, реквизит и расходные материалы ведутся в 1С на забалансовых счетах — не как ОС. В веб-сервисе они учитываются в отдельных блоках (АХО в проектах, расходники в отдельном модуле).

**Требует уточнения на встрече:**
- На каких именно счетах ведутся АХО и расходники — один счёт или разные?
- Возможна ли выгрузка забалансовых позиций через HTTP-сервис?
- Нужна ли привязка серийных номеров к забалансовым позициям или достаточно наименования?

**Предполагаемый ответ (если реализуемо):**

```json
[
  {
    "inv_no": "МЦ-000045",
    "name": "Стол переговорный",
    "type": "aho",
    "account": "012"
  },
  {
    "inv_no": "МЦ-000046",
    "name": "Бумага А4, пачка",
    "type": "consumable",
    "account": "012"
  }
]
```

| Поле | Тип | Описание |
|---|---|---|
| `inv_no` | string | Номер позиции |
| `name` | string | Наименование |
| `type` | `"aho"` / `"consumable"` | Тип для маршрутизации в веб-сервисе |
| `account` | string | Забалансовый счёт |

## Метод 5 — Webhook при списании ОС ⚠️ требует уточнения

Вместо polling раз в 30 минут — push-уведомление от 1С при изменении статуса ОС.

**Требует уточнения на встрече:**
- Поддерживает ли конфигурация исходящие HTTP-запросы?

**Если поддерживается**, 1С при списании ОС отправляет:

```
POST https://<supabase-project>.supabase.co/functions/v1/asset-written-off
Content-Type: application/json
X-Secret: <shared_secret>

{
  "inv_no": "ОС-000123",
  "written_off_at": "2025-11-01"
}
```

Веб-сервис автоматически обновит статус оборудования на «Списано» без задержки в 30 минут.

## Дополнительные требования

### CORS

Запросы к API будут идти с сервера Supabase Edge Functions (не из браузера), поэтому CORS-заголовки не требуются. Достаточно стандартного HTTPS + Basic Auth.

### Обработка ошибок

При ошибке на стороне 1С ожидается HTTP-код `5xx` с телом:

```json
{
  "error": "Описание ошибки"
}
```

### Нагрузка

- `GET /assets/free` — вызывается пользователем при открытии формы добавления оборудования (единичные запросы)
- `POST /assets/sync` — вызывается при сохранении новой карточки (единичные запросы)
- `POST /assets/status/batch` — фоновое задание раз в 30 минут, пакет до ~100 номеров за запрос

## Что нужно от интегратора

1. **URL базового адреса** HTTP-сервиса в 1С (например: `https://1c.company.ru/base/hs/equipment/`)
2. **Логин и пароль** технического пользователя для Basic Auth
3. **Подтверждение полей**, доступных для выгрузки по ОС
4. **Ответы по забалансовому учёту** — возможность выгрузки АХО и расходников, структура счетов
5. **Ответ по webhook** — поддерживает ли конфигурация исходящие HTTP-запросы
6. **Тестовая среда** (база данных 1С для тестирования до боевого запуска)
7. **Ориентировочные сроки** публикации HTTP-сервиса

---

## Контакт со стороны веб-сервиса

Разработчик веб-сервиса предоставит:
- Тестовые запросы (curl/Postman) для проверки каждого метода
- Список IP-адресов Supabase Edge Functions (если нужен whitelist)
- URL и секрет для webhook (метод 5, если будет реализован)
