# Процесс постановки оборудования на учёт

Описание действий сотрудников при сличении объекта учёта в 1С и веб-сервисе.

---

## Составные объекты (ПК и другие комплекты)

### Контекст

Некоторые объекты учёта физически состоят из нескольких компонентов — например, рабочее место (ПК): системный блок, монитор, клавиатура, мышь. Компоненты могут поступать в разные дни, что растягивает процесс постановки на учёт.

**Как это устроено в 1С:**
- Весь комплект — **один ОС** с одним инвентарным номером
- Компоненты учитываются внутри ОС (зависит от конфигурации и учётной политики)
- Согласно **ФСБУ 6/2020** (компонентный подход): если компоненты имеют разные сроки полезного использования — они могут амортизироваться отдельно и требуют раздельного учёта
- **Уточнить у бухгалтерии:** применяют ли компонентный подход ФСБУ 6/2020?

### Процесс для составного объекта

**Шаг 1 — Сотрудник склада создаёт родительскую карточку**
- Создаёт карточку «ПК рабочее место №3» со статусом **«Комплектуется»**
- Это сигнал системе и бухгалтерии: здесь будет составной ОС, компоненты ещё поступают

**Шаг 2 — По мере прихода компонентов**
- Каждый компонент оформляется отдельной карточкой и привязывается к родителю
- Веб-сервис уведомляет 1С: пришёл компонент, он входит в состав «ПК рабочее место №3»
- Бухгалтерия видит поступления и знает, что это части будущего ОС — не отдельные единицы

**Шаг 3 — Комплект собран**
- Сотрудник склада меняет статус родителя на **«Готов к сверке»**
- Родительская карточка появляется в списке несведённых с 1С
- Бухгалтерия заводит один ОС, присваивает инвентарный номер

**Шаг 4 — Сверка**
- Инвентарный номер привязывается только к **родительской** карточке
- В 1С обратно уходит серийный номер системного блока (как идентификатор комплекта)
- Дочерние карточки с 1С не сводятся — учитываются только в веб-сервисе

### Вопросы для уточнения на встрече

1. Применяют ли **компонентный подход ФСБУ 6/2020**? Если да — монитор и системный блок могут быть отдельными ОС
2. Есть ли в конфигурации **документ «Комплектация ОС»**?
3. Как бухгалтер сейчас видит компоненты внутри ОС — есть ли вкладка «Состав» в карточке ОС?

---

## 1. Поступление

- Оборудование поступает в компанию вместе с накладной
- Оборудование направляется на **склад**, накладная — в **бухгалтерию**

---

## 2. Сотрудник склада — создание карточки в веб-сервисе

- Открывает веб-сервис, создаёт новую карточку оборудования
- Заполняет все поля: модель, серийный номер, фото, категорию и т.д.
- Поле **«Инвентарный номер»** оставляет пустым — номер ещё не присвоен
- Оборудование уже доступно для работы (можно выдавать, добавлять в проект)

---

## 3. Бухгалтерия — проведение в 1С

- Проводит накладную, заводит номенклатуру
- Тип учёта определяет формат номера:
  - **ОС** → присваивается инвентарный номер
  - **Малоценка / забалансовый учёт** → присваивается порядковый номер
- После проведения 1С **автоматически передаёт** в веб-сервис: номер + наименование номенклатуры

---

## 4. Сотрудник склада — сверка карточки

- Открывает карточку оборудования, которое ещё не сведено с 1С
- Нажимает на поле **«Инвентарный номер»**
- В поле появляется выпадающий список — все номера из 1С, ещё не привязанные к карточкам веб-сервиса (номер + наименование из 1С)
- Выбирает нужную позицию из списка
- В карточке отображается только номер (без наименования из 1С)
- Сохраняет карточку

---

## 5. Обратная синхронизация в 1С

- После сохранения веб-сервис **отправляет в 1С серийный номер** оборудования
- Серийный номер записывается в сведённую номенклатуру в 1С
- Позиция исчезает из выпадающего списка несведённых номеров
